# 漫畫偵測與逐頁校正

先讀專案根目錄的 [Agent.md](../../../Agent.md)；兩類選區與保存規則見 [docs/two_class_project.md](../../../docs/two_class_project.md)。只做偵測可使用 CLI，無需啟動 GUI 或 MCP；也可復用正在執行的 GUI。需要校正時，透過 GUI 及其 MCP 操作，圖片由 AI 逐頁視覺判斷，選區由 GUI 編輯核心保存，不以直接改寫 NPZ 或離線批量處理代替逐頁審查；只做偵測時，核對任務結果及保存即可，不自行展開逐頁校正。

## 分批校對與會話隔離

先依要求與已有結果判斷是否需要偵測；需要且已授權的偵測由主代理使用下文 CLI 直接執行並核對結果，不需要另派 GUI 子代理。已有結果的校正任務直接續做，分批或交接不觸發重新偵測。只將逐頁校對委派給新會話，建立時使用 `fork_turns="none"`，交付專案 Skill、目標資料夾、已分配的 GUI `instance_id`／PID、明確頁碼批次及必要的操作契約，不攜帶上一批圖像、token 或試錯記錄。先依 `list_pages` 的實際校對標記找待校對頁，再按列表順序分批：每次取 20 頁，若剩餘少於 40 頁，最後一批一次處理全部剩餘頁。例：39 頁直接一批；59 頁分 20、39；201 頁分 9 批 20 頁及最後 21 頁。批次產生器及 CLI 用法見 [校對會話操作](references/review_sessions.md)。

同一會話及同一 GUI 的批次串行，前批使用 `handoff` 確認保存及指定頁面實際校對標記後才交下一批；不同會話可各用獨立 GUI 處理不同圖片資料夾，MCP 可並行。每個會話先 `bind` 認領 GUI ID、PID 和資料夾，同一 GUI 不可由另一會話同時認領；後續 MCP 經綁定客戶端呼叫，單次呼叫與切換在該 GUI 的短事務鎖下完成。存量舊 binding 須重新執行 `bind`，完成後用 `release` 釋放認領。切換本會話的資料夾必須明確使用 `switch`，不可在普通參數中覆蓋 `instance_id` 或取用另一會話的頁面 token／預覽。GUI 重啟後重新綁定。MCP 操作不持有桌面鎖；只有 Computer Use 的實際滑鼠／鍵盤輸入使用全機共享桌面鎖，持鎖期間仍須確認畫面屬於目標 GUI。

主代理只彙整實際完成頁數、保存狀態與下一批位置；使用者要求耗時時才保留必要的起止時間和階段。多個資料夾同時做 CLI GPU 偵測時，主代理以 `detect_queue.py --device gpu -- <偵測命令>` 排隊，僅鎖住 GPU 偵測子進程；明確使用 CPU 時可用 `--device cpu` 繞過。完成通知只在整個目標資料夾已完成並保存、且使用者已授權通知時送出，不按批次發送。認領、桌面鎖與 GPU 佇列只約束遵循此流程的進程，不提供對其他工具或同資料夾多程序編輯的強制隔離。

選擇 GUI 路徑且已接入專案 MCP 時，優先用它開專案、偵測、跳頁、讀取同版原圖／合成預覽，以及執行視覺確認後的精確選區；契約及座標格式見 [MCP 使用說明](../../../docs/mcp.md)。Computer Use 用於實際介面核對、筆刷／魔法棒／局部副本等尚未暴露的編輯。未接入或客戶端沒有新工具時，沿用 GUI 操作；不要憑文件假定工具可用。僅測試程式功能時，按使用者指定的測試範圍操作，不自行展開整章監修。

## 先依要求與專案狀態選擇流程

先核對磁碟上已有的正式資料與各頁狀態，再決定執行階段及使用 CLI 或 GUI。是否為舊專案取決於已有資料，不取決於是否新聊天、剛重開程式或換了操作視窗。

| 使用者要求 | 執行範圍 |
| --- | --- |
| 偵測／只跑偵測 | 對尚無結果的新專案偵測指定範圍，核對結果及保存後結束，不自動校正。舊專案先適用下述重跑限制。 |
| 打開舊專案／繼續校正 | 讀取既有結果及校對進度，依要求查看或續做；不重跑偵測。僅要求打開時不自行開始校正。 |
| 完整去字／偵測並校正 | 新專案先偵測再逐頁校正；已有偵測結果的專案復用結果，直接校正。 |
| 重新偵測／重跑偵測 | 使用者明確要求後，才重跑指定範圍；沿用 GUI 保護人工修改的機制。 |

- 已有偵測結果的頁面，只有使用者明確要求重新偵測才可重跑。打開專案、繼續校正、調整模型設定、有 OTHER 或尚未校對，都不代表授權重跑。成功偵測但沒有選區的頁面也算已有結果。
- 舊專案有未偵測頁、失敗頁或資料讀取異常時，先說明狀態，不自動補跑或重跑整章，也不用重新偵測代替資料修復。需要補跑時依使用者要求只處理對應頁面；若僅說「偵測」但範圍會包含已有結果，先釐清要補未偵測頁還是重新偵測已有頁。
- **已偵測不等於已校對。** 只做偵測不操作「完成本頁」或 `mark_page_reviewed`，不能回報為逐頁校正完成。

## 無界面只做偵測

使用者要求「不啟動界面／無界面／命令行偵測」時，使用專案已有的 CLI，不為此啟動 GUI 或 MCP。此路徑只負責偵測與保存；需要後續校正時再開 GUI 載入同一專案。未指定操作方式時，可依現有環境選擇 CLI 或已開啟的 GUI。

已安裝依賴及模型後，在專案目錄執行（Windows 將 Python 路徑換成 `.venv\Scripts\python`）：

```bash
.venv/bin/python detect_solid_inpaint_folder.py "/absolute/path/to/image_folder"
```

- `--start-page 5 --end-page 8` 指定自然排序後從 1 開始、包含首尾的頁碼；預設只處理範圍內未完成頁，跳過成功頁（含沒有選區的空白頁）及已有人工資料。
- CLI 的預設跳過機制不取代上節的任務範圍判斷。只有使用者明確要求重新偵測，才加 `--redetect`，並限於指定範圍；不能因跳過了已有頁面就自行加上此旗標。
- `--detector`、`--device`、`--bubble`／`--no-bubble` 依要求選用。未指定時使用專案已保存的模型參數及氣泡設定，新專案使用預設值；不讀寫 GUI 全局偏好。完整參數見 [README](../../../README.md) 的「無界面批量偵測」。
- 等待程序結束，核對偵測／跳過／失敗計數、實際涵蓋範圍及 `raw/project.json` 保存狀態。退出碼 `0` 為成功、`1` 為頁面失敗、`2` 為參數或啟動錯誤。原圖變更或已有正式資料缺失／損壞時先回報，不以重跑自動修復；失敗不能回報為完成。
- 結束時明說只完成偵測、尚未逐頁校正；不標記已校對，不自行導出 PDF／PSD。不要同時以 GUI 與 CLI 修改同一專案，專案沒有跨程序編輯鎖。

## 處理標準（逐頁校正時適用）

- 處理章節標題、人物對話、獨白／旁白，以及需要去字的框外擬聲詞；包含漏掉的小字、標點、假名與字形邊緣。依使用者指定範圍調整。
- 氣泡外或壓在衣物、線稿上的明確人物獨白／旁白仍是處理目標；先按敘事用途辨識。背景複雜時改用 OTHER，不可僅因沒有氣泡或背景不純色就當成報告／文章正文跳過。
- **保留畫面上的頁碼。** 頁碼若誤入純色填充或 OTHER，清除其兩類選區並恢復原圖，不把頁碼當成去字目標。續做時若使用者要求僅後續頁面適用，從當前未完成頁起執行，不因此回改先前已完成頁。
- 球衣字樣與背號、品牌、廣告、店招、介面導覽及署名通常屬於畫面內容，恢復其誤判選區。劇情引用的文章標題／正文需依敘事用途判斷，勿連同周圍網頁介面一起清除。
- 優先完成對話、獨白／旁白、章節標題與擬聲詞。複雜的非擬聲詞區域（例如報告、新聞正文）若一次合理嘗試後仍需反覆描邊、撤銷或判斷用途，就停止處理該區，用 F3 清除該區兩類選區並恢復原圖，留給後續人工決定；不要留下半完成的選區或錯誤填色。後續仍有人工作複核，不必為不確定是否需要去字的區域反覆嘗試；使用者明確要求精修該區時再繼續。
- 白色或其他可靠純色底用 **F1 純色填充**；保留原底色，黑底不要塗白。網點、漸層、線稿、衣物、人物或景物上的文字用 **F2 圖像修補**。
- **F2 保存 OTHER 待修復 Mask，並未實際修復圖像。** 複雜背景應標記待修復，不以大塊白色掩蓋。
- 框外文字沿字形或緊貼文字的小區域選取；斜字、大型擬聲詞與分散部件優先用套索／局部放大，避開臉、手、衣褶、氣泡邊框與動作線。不要只為省操作而用整格大框。
- 保留來源圖片，沿用專案的非破壞式 overlay／OTHER 保存方式。原圖不需要覆寫。

## 執行步驟

### 1. GUI 路徑：確認專案與已有狀態

無界面只做偵測直接依上節 CLI 流程執行；以下步驟適用於使用 GUI 偵測或逐頁校正。

1. 從目前 GUI 狀態確認應用程式、已載入資料夾與圖片數量。若程式未啟動，依 Agent.md 啟動；切換到使用者指定的資料夾，核對完整路徑。MCP 可用時先以 `list_app_instances` 辨認視窗，後續呼叫沿用目標 `instance_id`，避免雙開時操作另一個專案。
2. 以 `list_pages` 或 GUI 核對各頁偵測、失敗、校對及保存狀態，依上表選擇流程；不要先開「偵測並生成」或呼叫 `start_detection` 再判斷是否需要。
3. 續做先核對實際完成頁面；「已校對 8 頁」不代表前 8 頁連續完成。依指定位置或列表中第一個未校對頁續做。只保留專案路徑、實際完成頁面、目前／下一未校對頁及保存狀態，不整理逐項問題、座標、試錯過程或校正清單。
   需要 Computer Use 操作畫布時，開始監修或移到另一個顯示器後，先按「整理監修視窗」，使視窗在目前螢幕可用範圍內恢復一致的工作尺寸，再取得新畫面。不要沿用其他螢幕的物理像素座標。僅使用綁定 MCP 的原圖座標取圖及編輯時，不依賴桌面視窗尺寸，無需為整理視窗切換至 Computer Use；同名多視窗無法可靠定向時不可猜測點擊。只做偵測不需要進入逐頁監修。

### 2. 偵測（僅在本次要求需要且授權時）

1. 只在流程確定需要偵測後，開啟「偵測並生成」或使用 MCP。遵照使用者指定設定；未指定時先檢視已記住的模型、裝置、Mask 膨脹、塗白範圍和氣泡填充設定。不要將某台電腦的 MPS 或某一次使用的模型寫成所有人的固定要求。
2. 新專案且本次要求需要偵測時，未指定範圍才預設全部頁面；子範圍、補跑或重跑依使用者要求，不能把校正續做位置當成偵測起點。GUI 起止頁每次預設回全頁，不會記住上次子範圍，開始前須核對。
   真正要做全話偵測時，MCP `start_detection` 省略 `end_page`，由程式取實際頁數；核對回傳的專案總頁數、任務範圍及檔名清單，勿沿用上一話的 28／30 頁。補跑只指定已授權的缺失或失敗頁面範圍，不能包含未授權重跑的已有結果。
3. 已有選區時，重跑會更新自動區域並保護人工修改，仍須確認使用者已要求重新偵測及範圍。MCP 只有取得這項要求後才傳 `allow_redetect=true`；不能為繞過 `confirmation_required` 自行改成 true。
4. 開始偵測後觀察進度直到完成，核對總頁數、實際涵蓋範圍、失敗頁及保存結果。指定子範圍任務完成，只代表該範圍完成；有失敗先回報，不擅自重新提交整個任務。
5. 模型及氣泡填充選項會在成功開始後保存為全局偏好，跨專案及重開沿用；取消或未成功啟動不更新偏好。專案內仍保存當次處理參數。
6. **只做偵測到此結束**：依第 4 節核對保存，回報偵測結果及尚未逐頁校正；只有要求包含校正時才進入第 3 節。

### 3. 逐頁校正（僅在要求包含校正時）

依圖片列表順序逐頁查看，不只查看標示「有 OTHER」的頁。以固定顯示的目前頁碼／檔名及列表選中項確認目前頁；偵測任務進度不代表正在檢查的頁。

每頁對照左側原圖／Mask 與右側合成預覽：

有 `get_review_bundle` 時，可一次取得同版原圖與合成圖，以及頁面身分、保存狀態和 `page_token`。整頁檢查後，用原圖座標 `crop` 放大小字及疑點；不得只看自動選區清單或局部裁切而省略整頁。縮圖看不清的字須查看足夠解析度的局部圖或 GUI 放大。

預覽若疑似整片黑色或內容與頁面不符，先核對回傳的頁碼／檔名、裁切座標與範圍，再檢查保存的 PNG 像素或重新取得整頁同版圖；不能用 `restore` 清除選區來診斷可能的預覽或裁切錯誤。

1. 找出目標文字，檢查是否完整選中，以及該填色還是待修復。
2. 恢復誤判：優先使用 F3「恢復原圖」，以矩形或套索左鍵清除範圍內兩類選區，直到右圖的畫面內容恢復；局部選區需避開附近正確的去字。
3. 補選漏字，或將錯誤填白的複雜背景文字轉到 F2。複雜非擬聲詞依上述停止條件恢復原圖並留人工決定，不反覆精修。保留同頁內正確的對話框填色，避免大範圍轉入帶走氣泡邊緣。
4. 放大檢查框外字及鄰接人物的細小區域；確認沒有文字殘邊、錯色填充或多餘的圖像選區。
5. 確認右圖效果及保存狀態後，使用「完成本頁並到下一頁」。只在實際看過並確認本頁後標記已校對；OTHER 待修復，以及依上述停止條件保留原圖的非擬聲詞，不妨礙本輪校對完成，但不能宣稱這些區域已去字或已修復。保存失敗不能標記或離頁。已校對頁再修改會回到待回看，完成後重新確認；不能把「已偵測」算作「已逐頁校正」。

MCP 精確編輯使用 `apply_page_edits`：攜帶剛看過的 `page_token`，以原圖像素描述矩形或多邊形。只把同頁、已看清楚的選區放在一批；複雜擬聲詞可分開描繪各部件，不能用整格大框代替。純色新增須明確指定已確認的 `color_rgb`，黑底用黑色；不可靠背景用 OTHER。`transfer` 只轉已有選區，補漏字應用 `add`。

每批完成後讀取新預覽，放大核對修改範圍及邊緣；需要回復時使用帶新 token 的 `undo_page_edit`。切頁、重載、來源或內容變更造成 token 過期時，重新取圖判斷，不直接套上新 token 重送舊座標。保存失敗時先排除或重試保存，核對目前圖像後才決定下一步，不盲目重送編輯。

離頁前再次看整頁合成，確認無新增誤傷並已保存，才呼叫 `mark_page_reviewed` 或點 GUI 完成按鈕。`advance=true` 回傳的下一頁仍是未驗收的新頁，不得連續自動標記。程式的版本／保存檢查不能代替視覺驗收。

### 4. 保存與完成核對

- 編輯會自動保存；確認狀態列沒有保存錯誤。局部視窗是副本，必須按「套用」才會寫回主頁，取消則丟棄局部修改。
- 回到修改較多的頁重新載入，核對選區、顏色、已恢復的誤判與待修復標記仍保留。保存失敗時留在當前頁排除問題，不要繼續假定已保存。
- 正式資料位於 `<圖片資料夾>/ctd_inpainted/raw/project.json` 與 `raw/pages/<完整原圖檔名>.npz`。`raw/cache/` 是輔助快取；導出不是保存的必要步驟。
- 依本次範圍分開回報偵測頁數、實際逐頁校對頁數、失敗頁、OTHER 頁數與保存確認；只做偵測時明說尚未逐頁校正，不列逐項問題或校正清單。若有複雜非擬聲詞保留原圖，概括說明留人工複核即可。OTHER 數字表示含待修復選區的頁數，不是文字區塊數。尚未檢查完時明確交代已完成與剩餘頁。

## 介面操作要點

| 功能 | 用法與注意 |
| --- | --- |
| F1／F2 | 選擇純色填充／待修復類型；兩類互斥，添加到一類會撤掉同位置另一類。 |
| F3 恢復原圖 | 左鍵矩形／套索清除兩類 Mask；從不相容工具啟動時切到矩形，可撤銷。 |
| F5／F6／F7／F8 | 矩形／筆刷／魔法棒／套索。套索逐點建立，Enter 或雙擊閉合，Backspace 退一點，Esc 取消。 |
| F9／F10 | 添加／從目前類型減去。切工具保留相容模式；不相容時回到添加，操作前核對固定顯示的類型、工具及模式。 |
| F12 從其他轉入 | 只轉移本次選區碰到的另一類既有 Mask，不能補出完全漏選的字；轉入 F1 可能需要選擇填色。 |
| F11 局部交集 | 會裁切碰到的既有區塊，並非一般添加；只在需要收窄時使用。 |
| 右鍵拖矩形 | 清除範圍內兩類 Mask；Computer Use 不支援此輸入時，分別在 F1、F2 減去。 |
| 撤銷／重做 | 編輯錯誤時使用，並重新看右圖確認；不要僅憑按鍵成功就認定回復完成。 |
| 批處理 | 將全部選區轉為指定類型且不可撤銷，逐頁校正不使用。 |
| 原圖／Mask 滑桿 | 0% 看原圖，100% 看黑底 Mask；左側的白色顯示不保證實際填色為白色。 |
| 黃色／粉色提示 | 黃色是背景取樣提示；可取消「顯示背景選區」核對原圖。粉色是 OTHER，顏色可由使用者修改。不要把取樣提示當成破壞或漏修。 |
| PS 擴展預覽 | 只影響右側淡色外圈，不改變輸出的 OTHER，不能用它代替補選文字殘邊。 |
| F4 | 兩圖適應視窗；先確保整個視窗可見，視窗或工具列改變大小後重新觀察座標。 |
| 整理監修視窗 | 依目前顯示器可用範圍置中、限制邏輯尺寸並重新適應畫布；切螢幕後重新使用及讀取畫面。 |

新增純色區會沿用鄰接保存色或依背景取樣；取樣不足會彈出選色器，預設白色不代表已判定背景為白色。一般滾輪平移，Option／Alt＋滾輪縮放，Cmd／Ctrl＋加減鍵也可縮放。

Computer Use 的元素索引與畫布座標以最新畫面為準，不複用上次電腦或頁面的數值。每批操作後取得新狀態；切工具、開局部視窗、縮放或改視窗大小後，重新截圖再畫選區。魔法棒可能連通到背景，先小範圍試選並檢查；若溢出立即撤銷，改用套索或筆刷，不反覆累加錯誤選區。
